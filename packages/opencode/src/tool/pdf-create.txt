Creates a paginated PDF document from structured content and saves it inside the current project.

Usage:
- Use this tool to produce read-only deliverables such as final approval notes, certificates, and reports for distribution.
- `path` is the project-relative location of the finished file, for example "deliverables/approval-note.pdf". Use forward slashes; the file is written inside the project directory and an existing file at that path is replaced.
- The PDF is validated before delivery so it opens in standard PDF readers.
- After the tool succeeds, tell the user the saved path from the result.
- Prefer docx_create when the user needs to edit the document afterwards.
- Do NOT attempt to create PDF files using code execution - use this tool instead.

Document Structure (`contents`):
- `title`: Optional document title (appears in file properties)
- `author`: Optional author name (appears in file properties)
- `sections`: Array of content sections, each with:
  - `type`: "heading" | "paragraph" | "table" | "page-break"
  - `text`: The content text for headings and paragraphs
  - `level`: For headings, the heading level (1 is the largest)
  - `rows`: For tables, a 2D array of cell strings (first row is the header)

Best Practices:
- Structure content logically with clear headings
- Use tables for tabular data rather than trying to format with spaces
- Keep paragraphs focused and concise
- Use "page-break" to start a new page before a major section
